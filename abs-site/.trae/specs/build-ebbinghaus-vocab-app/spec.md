# 艾宾浩斯背单词应用 Spec

## Why
用户需要一套基于艾宾浩斯遗忘曲线的背单词应用，在遗忘临界点前主动回忆，而非一次性死磕。当前 `abs-site` 目录为空，需从零创建一个完整的 Web 应用，实现「周期设定 → 每日执行 → 标记淘汰」全流程自动化。

## What Changes
- 在 `abs-site/` 中创建全新的独立 Web 应用项目（FastAPI + SQLAlchemy async + PostgreSQL + 原生 JS 前端）
- 复用 `pro-site` 的技术栈和设计令牌体系（三栏布局、卡片风格、contenteditable 行内编辑）
- 实现单词库管理（CRUD + 批量导入）
- 实现单元切分（每 10 词一小页，每天 20–50 新词）
- 实现艾宾浩斯 8 点复习引擎（5min / 30min / 12h / D1 / D2 / D4 / D7 / D15）
- 实现每日三轮复习流程（晨背 / 午过 / 晚过）
- 实现标记淘汰机制（✓ 通过 / △ 卡壳 / ★ 顽固）
- 实现复习优先级强制（到期复习 > 新词学习）
- 实现断更恢复（漏掉的节点顺延补测，不从头重来）
- 实现进度统计与仪表盘

## Impact
- Affected code: `abs-site/` 全新目录（后端 `app/`、前端 `web/`、配置 `.env`、启动 `run.py`）
- 复用 `pro-site` 的 `app/database.py`、`app/config.py` 架构模式
- 数据库: 复用 PostgreSQL（同一实例，新 schema 或独立表前缀 `vocab_`）

## ADDED Requirements

### Requirement: 单词库管理
系统 SHALL 提供单词的增删改查功能，每个单词包含：英文拼写、音标、核心释义（1–2 个）、例句。

#### Scenario: 添加单词
- **WHEN** 用户输入英文、音标、释义、例句并提交
- **THEN** 单词保存到数据库，返回完整单词对象

#### Scenario: 批量导入
- **WHEN** 用户粘贴多行文本（每行 `word|phonetic|definition|example`）并提交
- **THEN** 系统解析并批量创建单词，返回成功/失败计数

### Requirement: 单元切分
系统 SHALL 将单词按单元组织，每个单元默认 10 个单词，每天可学习 20–50 个新词（2–5 个单元）。

#### Scenario: 创建单元
- **WHEN** 用户创建新单元并选择或添加单词
- **THEN** 单元保存，单词关联到该单元，按 sort_order 排序

### Requirement: 艾宾浩斯 8 点复习引擎
系统 SHALL 为每个新学单词自动生成 8 个复习节点，间隔为：学完后 5 分钟、30 分钟、12 小时、第 1 天、第 2 天、第 4 天、第 7 天、第 15 天。

#### Scenario: 新词学习触发复习计划
- **WHEN** 用户在晨间学习完成一个单元的新词
- **THEN** 系统为该单元每个单词生成 8 条复习计划记录，计算每个节点的预计复习时间

#### Scenario: 到期复习推送
- **WHEN** 用户打开今日复习页面
- **THEN** 系统按到期时间排序展示所有到期复习项，复习优先级高于新词学习

### Requirement: 每日三轮复习流程
系统 SHALL 支持每日三轮复习：晨间（新学 + 到期复习）、午间（遮释义回忆）、睡前（顽固词复习）。

#### Scenario: 晨间学习
- **WHEN** 用户进入晨间学习
- **THEN** 系统先展示到期复习项，复习完成后才展示当日新词单元

#### Scenario: 午间快速复习
- **WHEN** 用户进入午间复习
- **THEN** 系统展示当日晨间学过的单词，遮住释义，用户看英文回忆，卡壳的标 △

#### Scenario: 睡前顽固词复习
- **WHEN** 用户进入睡前复习
- **THEN** 系统只展示标 △ 和 ★ 的单词，再次卡壳的标 ★

### Requirement: 标记淘汰机制
系统 SHALL 支持三种标记，并根据标记自动调整复习计划：

- ✓ 通过：3 秒内反应出核心义，该节点完成，跳到下一节点
- △ 卡壳：卡一下想起来，下个节点继续测
- ★ 顽固：完全想不起，进入顽固词本，下次复习提前到最近节点

#### Scenario: 标记 ✓
- **WHEN** 用户在复习时点击 ✓
- **THEN** 当前节点标记完成，下一个节点时间不变，单词连续通过计数 +1

#### Scenario: 标记 ★
- **WHEN** 用户在复习时点击 ★
- **THEN** 单词进入顽固词本，连续通过计数清零，在下一个最近节点重新测试

#### Scenario: 连续 3 周期通过 → 长期记忆
- **WHEN** 单词连续 3 个节点都标记 ✓
- **THEN** 单词状态变为「已掌握」，移出复习池，每月抽检一次

### Requirement: 复习优先级强制
系统 SHALL 强制复习优先于新词学习，当有到期复习未完成时，提示用户先完成复习。

#### Scenario: 有到期复习时阻止新词
- **WHEN** 用户尝试学习新词但有未完成的到期复习
- **THEN** 系统提示「有 N 个单词到期复习，请先完成复习」，新词学习入口置灰

### Requirement: 断更恢复
系统 SHALL 在用户断更后，将漏掉的复习节点顺延到当前日期补测，而非从头开始。

#### Scenario: 断更 3 天后恢复
- **WHEN** 用户断更 3 天后重新打开应用
- **THEN** 系统将所有过期的复习节点合并到今日待复习列表，提示「你有 N 个补测项」，不重置已通过的节点

### Requirement: 进度统计仪表盘
系统 SHALL 提供仪表盘展示：今日待复习数、今日新学数、已掌握单词数、顽固词数、累计学习天数、7 日复习趋势。

#### Scenario: 查看仪表盘
- **WHEN** 用户打开首页
- **THEN** 展示统计卡片和 7 日复习量折线图

### Requirement: 主动回忆界面
系统 SHALL 在复习时先隐藏释义，用户点击「显示释义」后才能标记 ✓/△/★。

#### Scenario: 复习交互
- **WHEN** 用户进入复习卡片
- **THEN** 只显示英文和音标，释义隐藏；用户点击「显示释义」后展示释义和例句，出现三个标记按钮

### Requirement: PDF 导出
系统 SHALL 支持将今日复习清单、单元单词表导出为 PDF。

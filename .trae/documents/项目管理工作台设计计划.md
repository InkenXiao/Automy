# 项目管理工作台设计计划

## 一、总结

在 `pro-site/` 下构建一个全栈项目管理工作台，参照 automy-site AI 工作台原型的三栏布局设计。后端使用 FastAPI + SQLAlchemy 2.0 async + asyncpg 连接 PostgreSQL（参数从现有 `.env` 读取），前端为单页三栏工作台（纯 HTML/CSS/JS）。整合现有"项目周报工具"和"项目进度计划"两个模块，新增"每周工作任务安排"模块，三者通过数据库外键实现任务关联。

## 二、现状分析

### 现有资源
- **pro-site/.env**：已配置 PostgreSQL 连接（host=`pg_db`, db=`ragKB`, user=`dbuser`, URL=`postgresql+asyncpg://`）
- **pro-site/信投AI2.0_项目周报工具.html**：纯前端周报工具，6 个模块（底座/数据/智能体/应用/需求/协调），"下周任务"为自由文本，数据存 localStorage
- **pro-site/20260710信投AI2.0项目进度计划V2.3 执行图.html**：甘特图，40+ 任务（3 阶段），任务字段含 id/name/phase/start/end/status/full，数据硬编码
- **automy-site/prototype/workspace/index.html**：AI 工作台原型，三栏布局（`.app-frame` → `__sidebar`/`__main`/`__right`），橙色系配色

### 关键关联需求
1. 周报"下周任务" → 可从"项目进度计划"中选择任务（关联），也可新增独立任务
2. "每周工作任务安排" → 任务默认来自周报"下周任务"，也可增加临时任务

## 三、数据模型设计

### 表结构（PostgreSQL）

```
modules (项目模块字典)
├── id              SERIAL PK
├── idx             VARCHAR(4)     -- '01','02'...
├── tag             VARCHAR(16)    -- 底座/数据/智能体/应用/需求/协调
├── title           VARCHAR(128)
├── owner           VARCHAR(64)
├── color           VARCHAR(16)    -- '#2563EB'
├── color_bg        VARCHAR(16)    -- '#EFF6FF'
└── sort_order      INT

phases (项目阶段字典)
├── id              SERIAL PK
├── name            VARCHAR(32)    -- 第一阶段/第二阶段/第三阶段
├── subtitle        VARCHAR(32)    -- 有得用/用起来/用得好
├── description     TEXT
├── start_date      DATE
└── end_date        DATE

progress_tasks (项目进度计划任务)
├── id              SERIAL PK
├── task_uid        VARCHAR(16) UNIQUE  -- 原始ID '1-1','M1'
├── name            VARCHAR(256)
├── phase_id        INT FK → phases.id
├── start_date      DATE
├── end_date        DATE
├── status          VARCHAR(16)    -- ongoing/planned/milestone/done
├── full_desc       TEXT           -- 完整描述（含责任方）
├── owner           VARCHAR(64)
├── is_milestone    BOOLEAN DEFAULT FALSE
├── created_at      TIMESTAMPTZ
└── updated_at      TIMESTAMPTZ

weekly_reports (项目周报)
├── id              SERIAL PK
├── title           VARCHAR(128)
├── week_range      VARCHAR(32)    -- '07.01 — 07.07'
├── week_start      DATE
├── week_end        DATE
├── overview_summary TEXT          -- 本周概览摘要
├── status          VARCHAR(16) DEFAULT 'draft'  -- draft/submitted
├── created_at      TIMESTAMPTZ
└── updated_at      TIMESTAMPTZ

weekly_kpis (周报-本周概览KPI)
├── id              SERIAL PK
├── report_id       INT FK → weekly_reports.id ON DELETE CASCADE
├── module_id       INT FK → modules.id
├── progress_pct    INT DEFAULT 0  -- 0-100
├── status          VARCHAR(8)     -- 正常/关注/风险
└── UNIQUE(report_id, module_id)

weekly_progress_items (周报-本周进展)
├── id              SERIAL PK
├── report_id       INT FK → weekly_reports.id ON DELETE CASCADE
├── module_id       INT FK → modules.id
├── content         VARCHAR(512)   -- 事项标题
├── detail          TEXT           -- 补充说明/量化结果
└── sort_order      INT

weekly_plan_tasks (周报-下周任务) ★核心关联表
├── id              SERIAL PK
├── report_id       INT FK → weekly_reports.id ON DELETE CASCADE
├── module_id       INT FK → modules.id
├── progress_task_id INT FK → progress_tasks.id NULL  -- ★关联进度计划任务(可空)
├── name            VARCHAR(512)   -- 任务/事项名称
├── is_key          BOOLEAN DEFAULT FALSE  -- 是否重点
├── owner           VARCHAR(64)
├── plan_period     VARCHAR(32)    -- 计划周期
├── status          VARCHAR(16) DEFAULT '待开始'  -- 待开始/进行中/已完成
├── remark          TEXT
├── sort_order      INT
├── created_at      TIMESTAMPTZ
└── updated_at      TIMESTAMPTZ

weekly_risks (周报-风险与应对)
├── id              SERIAL PK
├── report_id       INT FK → weekly_reports.id ON DELETE CASCADE
├── seq             VARCHAR(4)     -- 'R1','R2'
├── title           VARCHAR(256)
├── coordination    TEXT           -- 需要协调的内容
├── urgency         VARCHAR(8)     -- 紧急程度
└── sort_order      INT

weekly_work_tasks (每周工作任务安排) ★核心关联表
├── id              SERIAL PK
├── week_start      DATE
├── week_end        DATE
├── plan_task_id    INT FK → weekly_plan_tasks.id NULL  -- ★关联周报下周任务(可空)
├── name            VARCHAR(512)   -- 任务名称
├── module_id       INT FK → modules.id NULL
├── owner           VARCHAR(64)
├── is_temporary    BOOLEAN DEFAULT FALSE  -- 是否临时任务
├── priority        VARCHAR(8) DEFAULT 'medium'  -- high/medium/low
├── status          VARCHAR(16) DEFAULT '待开始'  -- 待开始/进行中/已完成/已取消
├── planned_hours   DECIMAL(5,1)   -- 计划工时
├── actual_hours    DECIMAL(5,1)   -- 实际工时
├── remark          TEXT
├── sort_order      INT
├── created_at      TIMESTAMPTZ
└── updated_at      TIMESTAMPTZ
```

### 关联关系图
```
progress_tasks ──┐
                 │ (可选关联)
                 ▼
modules ←── weekly_plan_tasks ──┐ (可选关联)
                 ▲              │
weekly_reports ──┘              ▼
                          weekly_work_tasks
                          (默认来自周报下周任务,
                           is_temporary=true 为临时任务)
```

## 五、实施步骤

### 步骤 1：后端基础设施
**文件**：`requirements.txt`, `run.py`, `app/__init__.py`, `app/config.py`, `app/database.py`

- `requirements.txt`：fastapi, uvicorn[standard], sqlalchemy[asyncio], asyncpg, pydantic-settings, python-dotenv
- `app/config.py`：用 pydantic-settings 读取 `.env` 中的 `DATABASE_URL`、`POSTGRES_*` 等配置
- `app/database.py`：创建 `async_engine`（`create_async_engine(DATABASE_URL, echo=DEBUG)`）、`AsyncSessionLocal`（`async_sessionmaker`）、`get_db()` 依赖
- `run.py`：`uvicorn.run("app.main:app", host="0.0.0.0", port=8000, reload=True)`
- 验证：启动后端，确认能连接 PG（或至少不报配置错误）

### 步骤 2：数据库模型定义
**文件**：`app/models/base.py`, `app/models/module.py`, `app/models/phase.py`, `app/models/progress_task.py`, `app/models/weekly_report.py`, `app/models/work_task.py`, `app/models/__init__.py`

- `base.py`：`DeclarativeBase` + `TimestampMixin`（created_at, updated_at 自动维护）
- 按第三节表结构定义所有 ORM 模型，设置 `__tablename__`、外键关系、`relationship()`（含 `back_populates`）
- `__init__.py` 汇总导出所有模型，确保 Alembic/metadata 能发现全部表
- 验证：`from app.models import *` 无报错

### 步骤 3：Pydantic Schema 定义
**文件**：`app/schemas/*.py`

- 为每个实体定义 `XxxBase`、`XxxCreate`、`XxxUpdate`、`XxxOut` schema
- `WeeklyPlanTaskOut` 包含可选的 `progress_task` 嵌套对象（eager load 关联任务）
- `WeeklyWorkTaskOut` 包含可选的 `plan_task` 嵌套对象
- `WeeklyReportOut` 包含嵌套的 kpis、progress_items、plan_tasks、risks 列表

### 步骤 4：API 路由实现
**文件**：`app/routers/*.py`

核心端点：
```
GET    /api/modules                      模块列表
POST   /api/modules                      新建模块
PUT    /api/modules/{id}                 更新模块

GET    /api/phases                       阶段列表

GET    /api/progress-tasks               进度计划任务列表（支持 ?phase_id=&status= 筛选）
GET    /api/progress-tasks/{id}          任务详情
POST   /api/progress-tasks               新建任务
PUT    /api/progress-tasks/{id}          更新任务
PATCH  /api/progress-tasks/{id}/status   更新任务状态

GET    /api/weekly-reports               周报列表
GET    /api/weekly-reports/{id}          周报详情（含全部子表）
POST   /api/weekly-reports               新建周报
PUT    /api/weekly-reports/{id}          更新周报
DELETE /api/weekly-reports/{id}          删除周报

POST   /api/weekly-reports/{id}/plan-tasks          新增下周任务
PUT    /api/weekly-reports/{rid}/plan-tasks/{tid}   更新下周任务
DELETE /api/weekly-reports/{rid}/plan-tasks/{tid}   删除下周任务
POST   /api/weekly-reports/{id}/plan-tasks/link     从进度计划关联任务（传 progress_task_id + module_id）

GET    /api/work-tasks?week_start=YYYY-MM-DD        按周查询工作任务
POST   /api/work-tasks                               新建工作任务
POST   /api/work-tasks/from-plan/{report_id}        从周报下周任务批量生成工作任务
PUT    /api/work-tasks/{id}                          更新工作任务
DELETE /api/work-tasks/{id}                          删除工作任务
```

## 六、假设与决策

### 假设
1. PostgreSQL 服务已在 `pg_db:5432`（或可通过 .env 配置访问）运行，`ragKB` 数据库已创建
2. 表创建使用 `Base.metadata.create_all`（开发阶段简化），不引入 Alembic 迁移工具
3. 无需用户认证（内部单用户工具）
4. 前端不使用框架，纯 vanilla JS（与 automy-site 风格一致）
5. 保留原有两个 HTML 文件不修改（作为数据源参考和备份）

### 决策
1. **数据库 URL**：直接使用 .env 中的 `DATABASE_URL`（`postgresql+asyncpg://` 格式，SQLAlchemy async 原生支持）
2. **表创建**：开发阶段用 `create_all`，后续可引入 Alembic
3. **关联设计**：`weekly_plan_tasks.progress_task_id` 和 `weekly_work_tasks.plan_task_id` 均为可空外键，实现"可选关联"
4. **从周报导入周任务**：批量创建 `weekly_work_tasks` 记录，复制 `plan_task_id` 关联，允许导入后独立编辑
5. **配色**：复用 automy-site 橙色系（主色 #FF8C00、渐变 #FF8C00→#FF5D00、金色 #FFD700）
